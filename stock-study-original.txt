내가 ChatGPT를 활용해 주식을 공부한 방법

실제 종목 분석 → 심층 질문 → 과거 데이터 검증 → 백테스트 → 분석 시스템 개발

1. 이론보다 실제 종목 분석으로 시작했다

처음부터 주식 책이나 강의를 순서대로 공부하지 않았다.

실제 시장에서 급등하거나 급락한 종목을 발견하면 ChatGPT에게 이유를 물어보는 것으로 시작했다.

처음 사용한 질문

- 이 종목은 왜 올랐어?
- 거래량은 왜 갑자기 늘었어?
- 호재가 있는데 왜 떨어져?
- 과매도인데 왜 계속 하락해?
- 같은 업종인데 왜 이 종목만 급등했어?

처음에는 단순한 질문이었지만 답변을 듣고 끝내지 않았다.

답변에 등장하는 모르는 용어를 다시 질문하고, 그 용어가 실제 주가에 어떤 영향을 주는지 확인했다.

공부 방식: 실제 종목 → 궁금증 → 개념 학습 → 다시 종목 분석

---

2. 한 종목을 여러 단계로 끝까지 파고들었다

종목 하나를 분석할 때 단순히 차트와 뉴스만 보지 않았다.

분석을 반복하면서 점점 확인하는 범위가 넓어졌다.

1차: 주가와 거래량

질문 키워드

"RVOL · Volume Spike · 거래량 가속 · 1분봉 · 5분봉 · 15분봉 · RSI · 저점 방어"

실제 질문:

- 평소보다 거래량이 몇 배 증가했어?
- 가격 상승보다 거래량 증가가 먼저 나타났어?
- 5분과 15분 사이 거래량이 얼마나 가속됐어?
- 주가가 급락한 뒤 저점을 유지하고 있어?
- 과거에도 비슷한 거래량 변화가 있었어?

2차: 뉴스와 이벤트

질문 키워드

"FDA · Phase 2/3 · M&A · Contract · Earnings · Catalyst · D+7 · D+30"

실제 질문:

- 이 종목의 호재는 정확히 뭐야?
- 이미 발표된 뉴스야, 앞으로 발생할 이벤트야?
- 이벤트 날짜가 확정됐어?
- 계약이 발표만 된 거야, 실제로 종결된 거야?
- 향후 7일과 30일 안에 중요한 일정이 있어?

3차: SEC 공시

질문 키워드

"8-K · 10-Q · S-3 · 424B · ATM · PIPE · Warrant · Resale · ELOC"

실제 질문:

- 최근 SEC 공시 원문 확인해 줘.
- 유상증자나 자금조달 계약이 있어?
- 워런트 행사가격이 얼마야?
- 언제부터 행사할 수 있어?
- 실제 시장에 나올 수 있는 주식이 몇 주야?
- 기존 유통주식 대비 희석 규모가 어느 정도야?

특히 공시가 존재한다는 사실보다 실제로 언제, 얼마나 많은 주식이 시장에 공급될 수 있는지를 중요하게 확인했다.

4차: 재무와 공매도

질문 키워드

"Cash Runway · Cash Burn · Going Concern · Short Interest · CTB · FTD · Float"

실제 질문:

- 현재 현금으로 몇 분기를 버틸 수 있어?
- 추가 자금조달 가능성이 높아?
- 공매도 잔고가 유통주식 대비 얼마나 돼?
- 대차비용은 증가하고 있어?
- 숏커버가 발생할 만한 조건이 있어?

5차: 상승·하락 시나리오

마지막에는 다음을 함께 확인했다.

- 상승할 경우 주요 저항 가격
- 상승을 뒷받침할 조건
- 상승 시나리오가 무효화되는 조건
- 하락 시 주요 지지 가격
- 최악의 경우 발생할 수 있는 위험
- 진입·손절·목표가에 따른 손익비

이렇게 종목 하나를 가격 → 거래량 → 뉴스 → 공시 → 재무 → 수급 → 시나리오 순서로 분석했다.

---

3. 급등한 종목을 거꾸로 추적했다

가장 집중했던 공부는 급등하기 전에 어떤 신호가 있었는지 찾는 것이었다.

이미 급등한 종목을 발견하면 이전 시점으로 돌아가 분석했다.

실제 분석 순서

1. 급등이 시작된 날짜와 시간을 확인한다.
2. 상승 전 1~5거래일의 가격과 거래량을 확인한다.
3. 거래량이 평소보다 몇 배 증가했는지 계산한다.
4. 뉴스 발표 전 이상 거래가 있었는지 조사한다.
5. 이전 SEC 공시와 예정된 이벤트를 확인한다.
6. 당시 시점에서 실제로 알 수 있었던 정보만 분리한다.
7. 비슷한 패턴을 가진 다른 종목과 비교한다.

여기서 가장 중요하게 던졌던 질문은 다음과 같다.

"이 종목이 오르기 전에 발견할 수 있었던 근거가 있었을까?"

상승 이후의 결과를 알고 끼워 맞추는 분석이 되지 않도록 당시 공개된 정보와 이후에 확인된 정보를 구분하려고 했다.

---

4. 백테스트로 분석 기준을 비교했다

급등 종목을 여러 개 분석하다 보니 비슷한 특징이 반복해서 나타나는지 궁금해졌다.

그래서 ChatGPT를 활용해 분석 조건을 만들고 과거 데이터를 비교하는 백테스트를 진행했다.

실제로 비교했던 조건

분석 조건| 비교 내용
RVOL| 2배·3배·5배 이상
거래량 가속| 5분·15분 변화
가격 상승률| 10% 이내의 초기 신호
과매도| RSI 20 이하
저점 방어| 급락 이후 가격 유지
재점화| 이전 급등 후 거래량 재증가
이벤트| 뉴스·공시·확정 일정
포착 성과| D+1·D+3·D+5 변화

백테스트는 어떻게 진행했나?

① 가설 설정

예: "거래량이 평소보다 3배 이상 증가했지만 주가는 아직 크게 오르지 않은 종목이 이후 상승할 가능성이 있을까?"

② 조건별 데이터 수집

해당 조건을 만족한 과거 종목과 신호를 수집했다.

③ 성과 비교

신호 발생 후 가격 변화, 상승·하락 사례, 재알림 간격 등을 비교했다.

④ 조건 수정

특정 조건이 지나치게 많은 신호를 발생시키거나 유효한 종목을 놓치는 경우 기준을 수정했다.

⑤ 다시 검증

수정한 조건을 다른 기간과 종목에 적용해 비교했다.

실제 실험의 특징

- 종목을 50개 단위로 나누어 처리하는 배치 실험을 진행했다.
- 1일·2일·5일 재알림 간격을 비교했다.
- 거래량 가속 예외 조건을 실험했다.
- 포착 이후 D+1·D+3·D+5 성과를 확인하는 분석을 설계했다.
- 성공한 종목뿐 아니라 놓친 종목과 실패한 사례도 연구했다.

과거 재알림 실험에서 74.4%, 73.1%, 64.1% 등의 수치가 기록되기도 했다. 다만 이 수치들은 당시 실험의 평가 기준에 따른 것으로, 전체 투자 승률이나 실거래 수익률을 의미한다고 단정할 수 없다.

백테스트의 목적은 높은 승률을 보여주는 것이 아니라, 내가 세운 가설이 실제 데이터에서도 유효한지 확인하는 것이었다.

---

5. 놓친 종목을 집중적으로 복기했다

예상하지 못한 급등이 발생하면 그 종목을 다시 분석했다.

특히 다음과 같은 질문을 반복했다.

- 이 종목을 왜 놓쳤어?
- 거래량은 언제부터 증가했어?
- 상승률 제한 때문에 제외됐어?
- 위험 요소를 너무 높게 평가했어?
- 공시나 이벤트를 놓쳤어?
- 데이터 수집에 문제가 있었어?
- 어떤 조건을 수정하면 더 일찍 발견할 수 있었을까?

실제로 LUCD, NCPL, POLA, REED 등 여러 종목을 분석하면서 조기포착, 과매도, 자금조달, 반복 급등 등의 문제를 검토했다.

여기서 배운 것은 종목을 발견하는 능력과 투자 위험을 평가하는 능력은 별도로 발전시켜야 한다는 점이었다.

그래서 이상 거래를 찾는 1차 포착과 SEC·재무 위험을 확인하는 2차 검증을 구분하게 됐다.

---

6. AI의 답변을 검증하는 공부도 병행했다

ChatGPT를 사용하면서 답변이 틀리거나 오래된 정보를 제공할 수 있다는 사실도 경험했다.

특히 주식은 날짜와 숫자가 중요하기 때문에 확인 과정을 강화했다.

내가 사용한 검증 원칙

- SEC 원문을 최우선으로 확인한다.
- 가격과 거래량의 기준 시각을 확인한다.
- 뉴스 발표와 실제 이벤트 발생을 구분한다.
- 확정된 사실과 예상 시나리오를 분리한다.
- 잠재적 희석과 즉시 매도 가능한 물량을 구분한다.
- 상승 가능성뿐 아니라 최악의 시나리오도 확인한다.

AI가 제시한 결론에 의문이 있으면 다시 질문하고, 계산 근거와 원문을 요구했다.

---

7. 공부한 내용을 실제 시스템으로 만들었다

반복해서 분석하다 보니 매일 많은 종목을 직접 확인하는 데 한계가 있었다.

그래서 내가 연구한 분석 조건을 자동화하는 방법을 공부하기 시작했다.

개발하면서 배운 내용

- Python을 이용한 데이터 수집
- API 연결 및 데이터 갱신
- GitHub를 통한 코드 관리
- GitHub Actions 자동 실행
- GitHub Pages 대시보드
- Telegram 알림 구조
- 포착 이력 및 성과 기록
- 오류 분석과 코드 복구

처음부터 코드를 모두 이해한 것은 아니었다.

ChatGPT에게 필요한 기능을 설명하고, 코드를 작성하도록 요청하고, 실행 결과를 확인하면서 오류를 수정했다.

특히 정상 작동하던 코드가 수정 후 작동하지 않는 문제를 겪으면서 기존 코드 백업 → 최소 수정 → 테스트 → 정상 작동 확인이라는 개발 방식도 중요하게 생각하게 됐다.

---

8. 실제로 반복한 공부의 전체 과정

1단계 — 관찰

실제 시장에서 급등·급락·이상 거래 종목을 발견한다.

2단계 — 질문

왜 움직였는지, 어떤 정보가 영향을 주었는지 질문한다.

3단계 — 개념 학습

모르는 지표와 공시 용어를 실제 종목에 연결해 이해한다.

4단계 — 정밀분석

가격, 거래량, 뉴스, SEC, 재무, 공매도, 이벤트까지 분석한다.

5단계 — 역추적

급등 이전 시점으로 돌아가 사전 신호를 조사한다.

6단계 — 비교 연구

유사한 종목과 상승하지 못한 종목을 함께 비교한다.

7단계 — 백테스트

조건을 수치화하고 과거 데이터로 성과를 검증한다.

8단계 — 시스템 적용

검토한 조건을 자동 포착기에 반영한다.

9단계 — 실패 복기

놓친 종목과 잘못된 분석의 원인을 조사한다.

10단계 — 개선

새로운 결과를 바탕으로 조건과 분석 방식을 수정한다.

---

9. 이 공부 방식의 가장 큰 특징

내 공부는 단순한 질문과 답변의 반복이 아니었다.

하나의 종목에서 시작한 질문을 공시, 거래량, 기업 재무, 시장 구조, 과거 데이터까지 확장하는 방식이었다.

그리고 그 과정에서 얻은 지식을 다른 종목에 적용하고, 실제로 반복되는 특징인지 검증했다.

처음에는 "이 종목이 오를까?"를 물었다.

이후에는 "왜 올랐을까?"를 분석했다.

그다음에는 "오르기 전에 어떤 신호가 있었을까?"를 연구했다.

마지막으로 "그 신호를 수치화하고 자동으로 발견할 수 있을까?"를 고민했다.

그 과정이 종목 분석에서 백테스트, 그리고 자동 포착 시스템 개발로 이어졌다.

핵심 정리

실전 종목 중심 학습 + 끝까지 파고드는 질문 + SEC 원문 검증 + 급등 전 역추적 + 조건별 백테스트 + 실패 복기 + 자동화

이것이 내가 ChatGPT를 활용해 주식을 공부해 온 방법이다.

본 글은 개인적인 학습 경험을 정리한 것이며, 특정 종목에 대한 투자 권유나 수익 보장을 목적으로 하지 않습니다.
